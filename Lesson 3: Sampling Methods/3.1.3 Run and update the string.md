# Run and Update the String

After building the initial path, restrained QM/MM molecular dynamics simulations are performed for all images of the string. The trajectories are then used to update the string coordinates.

For the CM example, the string contains 21 images and two collective variables:

- C1–C8 forming bond
- C3–O4 breaking bond

The same string workflow can be used with different QM/MM potentials. Here, AM1/MM and GFN2-xTB/MM are shown separately because the QM energy and forces are evaluated differently in the two methods.

---

## 1. Set the restraints

For each image, harmonic restraints are applied to the two CVs:

```python
stream.charmm_script('set atom1 HETA 223 C1')
stream.charmm_script('set atom2 HETA 223 C8')
stream.charmm_script('set atom3 HETA 223 C3')
stream.charmm_script('set atom4 HETA 223 O4')

stream.charmm_script('resdistance reset')

stream.charmm_script(
    f'resdistance kval 1000.0 rval {rc1} 1.0 @atom1 @atom2'
)

stream.charmm_script(
    f'resdistance kval 1000.0 rval {rc2} 1.0 @atom3 @atom4'
)
```

`rc1` and `rc2` are replaced by the target CV values of each image from the current string file.

For example, the first iteration uses the values stored in:

```text
z0.txt
```

---

# 2. Run restrained QM/MM MD

Two QM/MM potentials are used in this tutorial. The string procedure is the same, but the MD scripts are different.

## Option A: AM1/MM

For AM1/MM, the QM region and AM1 Hamiltonian are defined directly through CHARMM:

```python
stream.charmm_script('define qm sele segid HETA end')
stream.charmm_script('quantum sele qm end am1 char -2')
```

### First MD run

The first MD simulation starts from `md0.crd`:

```python
dynamics_dict = {
    'cpt': True,
    'strt': True,
    'nstep': 20000,
    'timestep': 0.001,

    ...

    'tbath': 298.15,
    'firstt': 100.0,
    'finalt': 298.15,
    'teminc': 0.01,
}
```

This script is saved as:

```text
md_heat.py
```

### Following MD runs

For the following string iterations, the simulation is restarted from the previous restart file:

```python
stream.charmm_script(
    f'open read formatted unit 19 name md{nin}.rst'
)

stream.charmm_script(
    f'open write formatted unit 20 name md{nout}.rst'
)

stream.charmm_script(
    f'open write unformatt unit 21 name md{nout}.dcd'
)
```

and the dynamics use:

```python
dynamics_dict = {
    'cpt': True,
    'rest': True,
    'nstep': 20000,
    'timestep': 0.001,

    ...

    'tbath': 298.15,
    'firstt': 298.15,
    'finalt': 298.15,
    'teminc': 0.0,
}
```

This script is saved as:

```text
md_eq.py
```

Therefore:

```text
md0.crd
   |
   | md_heat.py
   v
md1.rst / md1.dcd / md1.crd
   |
   | md_eq.py
   v
md2.rst / md2.dcd / md2.crd
   |
   | md_eq.py
   v
...
```

## Option B: GFN2-xTB/MM

For GFN2-xTB/MM, the MD setup is similar, but the QM energy and gradients are obtained from xTB through the PyCHARMM callback introduced in the previous lesson.

The CHARMM QM electrostatic term is skipped:

```python
stream.charmm_script('define qm sele segid HETA end')
stream.charmm_script('quantum sele qm end am1 char -2')
stream.charmm_script('skip QMEL')
```

The xTB calculator is then initialized:

```python
calc = Calculator(
    Param.GFN2xTB,
    numbers,
    positions,
    charge=-2
)

calc.set_verbosity(VERBOSITY_MINIMAL)
```

During MD, the QM coordinates are sent to xTB:

```python
calc.update(positions)

calc.set_external_charges(
    numbers_sv,
    charges_sv,
    positions_sv
)

res = calc.singlepoint()
```

The xTB energy and gradients are returned to CHARMM:

```python
extb = res.get_energy() * 627.5095

dedcc = (
    res.get_gradient()
    * 627.5095
    / 0.529177
)

dedcc_mm = (
    res.get_pcgradient(numbers_sv.size)
    * 627.5095
    / 0.529177
)
```

The callback is registered with PyCHARMM:

```python
e_func = pycharmm.EnergyFunc(e_xtb)
```

The first string MD uses:

```text
md_heat_xtb.py
```

and the following restart simulations use:

```text
md_eq_xtb.py
```

Therefore, the xTB/MM sequence is:

```text
md0.crd
   |
   | md_heat_xtb.py
   v
md1.rst / md1.dcd / md1.crd
   |
   | md_eq_xtb.py
   v
md2.rst / md2.dcd / md2.crd
   |
   | md_eq_xtb.py
   v
...
```

The detailed PyCHARMM–xTB interface is described in the previous GFN2-xTB/MM lesson.

# 3. Run all 21 images

Instead of manually running each image, `launch_images_pycharmm.sh` is used to submit the simulations automatically.

First, define the image range:

```bash
export inf=1
export sup=21
```

and the desired string iterations:

```bash
for ((itr=1;itr<=5;itr++))
do
```

For each iteration, the previous string is used:

```bash
j=$(( ${itr} - 1 ))
```

Therefore:

```text
itr = 1  →  read z0.txt
itr = 2  →  read z1.txt
itr = 3  →  read z2.txt
...
```

---

## 4. Read the CV values

The target CV values for all images are read from the previous string:

```bash
index=`echo $inf | bc`

while read rc1 rc2 rc3 rc4
do
    rrc1[index]=$rc1
    rrc2[index]=$rc2
    rrc3[index]=$rc3
    rrc4[index]=$rc4

    index=`echo ${index}+1 | bc`

done < z${j}.txt
```

For the chemical string used here, `rrc1` and `rrc2` provide the target values for the C1–C8 and C3–O4 restraints.

---

# 5. Prepare and submit the MD for each image

The script loops through all 21 images:

```bash
for ((i=1;i<=21;i++))
do
```

The target CV values are inserted into the MD template:

```bash
sed \
-e s@zyin@${j}@g \
-e s@zyout@${itr}@g \
-e s@zy1@${rrc1[i]}@g \
-e s@zy2@${rrc2[i]}@g \
-e s@zy3@${rrc3[i]}@g \
-e s@zy4@${rrc4[i]}@g \
< md.py > md${itr}.py
```

The generated script is moved into the corresponding image directory:

```bash
mv md${itr}.py md${itr}.pbs img${i}
```

and submitted:

```bash
cd ${SLURM_SUBMIT_DIR}/img${i}

/usr/bin/sbatch md${itr}.pbs
```

Thus, one string iteration runs:

```text
                 zN.txt
                    |
        +-----------+-----------+
        |           |           |
        v           v           v
      img1        img2        ...       img21
        |           |                     |
       MD          MD                    MD
        |           |                     |
        v           v                     v
    mdN+1.dcd   mdN+1.dcd             mdN+1.dcd
```

---

# 6. Wait for all images to finish

The string should only be updated after all 21 MD simulations are complete.

The launch script checks whether `md${itr}.crd` has been generated in every image directory:

```bash
ndone=0

while [ ${ndone} -lt 21 ]; do

    ndone=0

    for ((i=1;i<=21;i++))
    do
        cd ${SLURM_SUBMIT_DIR}/img${i}

        if [ -e md${itr}.crd ]; then
            ndone=$(( $ndone + 1 ))
            echo ${ndone}' md are done'
        else
            echo 'img'${i}' md'${itr}' not done yet'
        fi
    done

done
```

When all 21 coordinate files are present, the string update can begin.

---

# 7. Update the string

After all images are finished, the trajectories are analyzed using:

```bash
./evolve_z_path_bond_ang_dihe_skip2000.exe \
restraints.txt z${j}.txt > log_${itr}.out
```

The restraint definition used for this calculation is:

```text
2 1000.0 1 2 0 0
2 1000.0 3 4 0 0

filein12
filein13
```

The string update program generates a new set of CV values:

```text
znew.txt
```

which is renamed according to the current iteration:

```bash
mv znew.txt z${itr}.txt
mv df.txt df_${itr}.txt
```

For example:

```text
Iteration 1:

z0.txt
   |
   +----> 21 restrained MD simulations
   |
   +----> trajectory analysis
   |
   +----> string update
   |
   v
z1.txt
```

The new `z1.txt` is then used as the restraint centers for the next iteration.

---

# 8. Repeat the string iterations

The complete procedure is repeated:

```text
z0.txt
   |
   v
21 restrained MD simulations
   |
   v
update string
   |
   v
z1.txt
   |
   v
21 restrained MD simulations
   |
   v
update string
   |
   v
z2.txt
   |
   v
...
```

The QM/MM potential used to generate the trajectories can be changed without changing the overall string-update procedure:

```text
                    Initial string
                       z0.txt
                          |
             +------------+------------+
             |                         |
             v                         v
          AM1/MM                  GFN2-xTB/MM
       md_heat.py               md_heat_xtb.py
       md_eq.py                 md_eq_xtb.py
             |                         |
             +------------+------------+
                          |
                          v
                21 restrained MD
                          |
                          v
                  update the string
                          |
                          v
                z1 → z2 → ... → zN
```

Once the string no longer changes significantly between iterations, the resulting path can be used to calculate the chemical free-energy profile.
