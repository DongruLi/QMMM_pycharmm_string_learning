In Lesson 2.2, we connected PyCHARMM with xTB so that GFN2-xTB can provide the QM energy and gradients.

We can now use this energy function to run **xTB/MM molecular dynamics (MD)**.

In this project, two MD scripts are used:

- `md_heat.py` starts the first MD simulation.
- `md_eq.py` continues the simulation from the previous restart file.

The basic workflow is:

```text
Initial structure
      |
      | md_heat.py
      v
     md1
      |
      | md_eq.py
      v
     md2
      |
      | md_eq.py
      v
     md3
      |
     ...
      v
     md5
```

---

> **Read the PSF and the starting coordinates**

The PSF file contains the system topology, while the CRD file contains the atomic coordinates.

psf_file = "../../charmm-gui-3767440248/step3_pbcsetup.psf"

```

For the first MD run, `md0.crd` is used as the starting structure.

The same periodic boundary conditions and nonbonded settings introduced in Lesson 1 are used here.

> **Register the xTB energy function created in Lesson 2.2**

```python
e_func = pycharmm.EnergyFunc(e_xtb)
```

After this step, PyCHARMM can call GFN2-xTB during the MD simulation to obtain the QM energy and gradients.

> **Check the energy before starting MD**

```python
energy.show()
```

This provides a simple check that the system and the PyCHARMM–xTB interface are working before dynamics starts.

## Apply restraints

During the reaction-path simulations, two distances are restrained:

- C1–C8: the forming C–C bond
- C3–O4: the breaking C–O bond

> **Define the atoms used for the two distance restraints**

```python
atom1 = pycharmm.SelectAtoms().by_res_and_type('HETA', 223, 'C1')
atom2 = pycharmm.SelectAtoms().by_res_and_type('HETA', 223, 'C8')

atom3 = pycharmm.SelectAtoms().by_res_and_type('HETA', 223, 'C3')
atom4 = pycharmm.SelectAtoms().by_res_and_type('HETA', 223, 'O4')
```

> **Apply harmonic restraints to the two distances**

```python
resd.str('RESET')

resd.str(
    'KVAL 1000.0 RVAL @r1 '
    '1.0 @atom1 @atom2'
)

resd.str(
    'KVAL 1000.0 RVAL @r2 '
    '1.0 @atom3 @atom4'
)
```

Here, `@r1` and `@r2` are the target values of the two distances.

Different target values are used for different images along the reaction path.

We will explain how these values are generated and updated in the **String Method** lesson.

## Set up the MD simulation

> **Prepare files for the trajectory and restart information**

```python
dcd_unit = pycharmm.CharmmFile(
    file_name='md1.dcd',
    file_unit=1,
    formatted=False,
    read_only=False
)

res_unit = pycharmm.CharmmFile(
    file_name='md1.rst',
    file_unit=2,
    formatted=True,
    read_only=False
)
```

The main output files are:

| File | Description |
|---|---|
| `md1.dcd` | MD trajectory containing many structures |
| `md1.rst` | Restart information for continuing the MD |
| `md1.crd` | Coordinates at the end of the MD |

---

## Run the first MD segment

The first simulation is started using `md_heat.py`.

> **Set the basic MD parameters**

```python
dynamics_script = pycharmm.DynamicsScript(
    leap=True,
    lang=True,

    start=True,

    timestep=0.001,
    nstep=20000,

    firstt=100.0,
    finalt=298.15,
    teminc=0.01,

    tbath=298.15,

    iunwri=res_unit.file_unit,
    iuncrd=dcd_unit.file_unit,

    nsavc=100,
    nsavv=0
)
```

The important settings are:

- `timestep = 0.001`: 1 fs time step
- `nstep = 20000`: 20,000 MD steps
- `firstt = 100.0`: starting temperature
- `finalt = 298.15`: final temperature
- `nsavc = 100`: save coordinates every 100 steps

This gives a total simulation time of:

\[
20000 \times 1~\mathrm{fs} = 20~\mathrm{ps}.
\]

> **Start the MD simulation**

```python
dynamics_script.run()
```

During the simulation, PyCHARMM repeatedly calls the `e_xtb()` function introduced in Lesson 2.2 to obtain the GFN2-xTB energy and gradients.

coor.write_card('md1.crd')

## Continue the MD simulation

After the first MD segment, `md_eq.py` is used to continue the simulation.

> **Read the previous restart file**

```python
stream.charmm_script(
    'open read formatted unit 19 name md1.rst'
)
```

The main difference from the first MD run is that the simulation now uses:

```python
'rest': True,
```

instead of:

```python
'strt': True,
```

This tells CHARMM to **continue the previous MD simulation rather than start a new one**.

The workflow therefore becomes:

```text
md0.crd
   |
   | md_heat.py
   v
md1.crd + md1.rst
   |
   | md_eq.py
   v
md2.crd + md2.rst
   |
   | md_eq.py
   v
md3.crd + md3.rst
   |
   ...
   v
md5.crd + md5.rst
```

---

## How this is used in the string method

The first MD segment starts from `md0.crd` using `md_heat.py`.
After this step, `md_eq.py` is used to continue the simulation from the previous restart file.

The workflow is:

```text
md0 → md1 → md2 → md3 → md4 → md5
       ↑      ↑      ↑      ↑
     restart restart restart restart

## What have we done?

In this lesson, we used the PyCHARMM–xTB interface to run restrained xTB/MM molecular dynamics.

The main workflow is:

```text
QM/MM system
     |
     v
GFN2-xTB energy + gradients
     |
     v
restrained xTB/MM MD
     |
     v
DCD trajectory + restart + final coordinates
```

The first MD segment is started with `md_heat.py`, and later segments are continued with `md_eq.py`.
